# スライム診断 設計図

## 先に決めた禁止

1. **生年月日以外を聞かない。** 時刻も出生地も聞かない。入口が軽いことが親しみやすさの条件で、
   時柱が要る話（紫微斗数・アセンダント）は星読みの担当
2. **MBTIを混ぜない。** 自己申告の値を根拠に入れない。全部を生年月日から出す
3. **使った暦を隠さない。** 日柱・月柱・節入りを結果の中に出す

## 入力

生年月日 1つだけ。

日柱は日本標準時0時で変わり、月柱は節入りで変わる。どちらも日付だけで確定するので、
時刻・場所を聞く必要がない。

## 計算（全部 hoshiyomi のものを読むだけ）

| 出すもの | 出どころ |
|---|---|
| 日柱・月柱の干支 | `koyomi.js` の `HOSHI_KOYOMI.build()` |
| 十二運・通変星・五行 | `toyo.js` の `shichu()` |

新規に書く計算はゼロ。対応表を引くだけ。

```
日干の五行        → 色    木=青 火=赤 土=黄 金=白 水=黒
日干 + 日支の十二運 → 景    UNSEI 配列と 1:1（JUNIKEI[UNSEI.indexOf(un)]）
月柱の shiStar     → 星    月支の蔵干本気から見た通変星（格局の定石）
景の強さ × 星の向き → ズレ  3×2 の表
```

`kanStar`（月干からの通変）も出るが、主役は `shiStar` にする。両方とも「使った暦」には出す。

## 出す順番

**景 → 色 → 星 → ズレ**

絵と名乗りが景なので、最初に読むのも景にする。色を先に読ませると視線が飛ぶ。

## 画面

**入力**
- 生年月日 + ボタン。それだけ

**結果**
1. 画像1枚（大きく）＋ 名乗り「青の、蕾」
2. 景の本文
3. 色の本文
4. 星の本文
5. ズレの本文
6. 折りたたみ ── 使った暦（日柱干支・月柱干支・節入り日時・十二運・通変星2つ・五行の数）

全部を開いた状態で出さない。畳む。

`koyomi.js` `toyo.js` は **hoshiyomi のものを相対参照する**。コピーしない。
（`app-theme.js` は星読みの「気になるところ」タブ用で、ここでは使わない。CSSは自前で持つ）

```html
<script src="../hoshiyomi/assets/koyomi.js"></script>
<script src="../hoshiyomi/assets/toyo.js"></script>
```

D:\00000 直下に両方が並んでいる前提。slime だけ単体で配る場合は壊れる。そのときはコピーする。

## ズレの判定表

| | 集める星 | 削る星 |
|---|---|---|
| 強（若木・蕾・満開） | 持て余す | 重なる |
| 中（芽・双葉・実り・根） | 持て余す | 足りない |
| 弱（色づき・落ち葉・土・風・種） | 重なる | 足りない |

集める＝並び株・絡み蔓・木漏れ日・恵み雨／削る＝香り・棘・野原・畝・鋏・支柱

## テスト（Node の vm で）

1. 日柱干支が hoshiyomi と一致するか（既知の日付をいくつか）
2. 120通り（12景 × 10星）が必ず3型のどれかに落ちるか
3. **60干支を全部回して、色ごとに起こる景が6つだけであることを確認する**
   （青と白に満開は来ない／赤・黄・黒に風は来ない）
4. 本文が全部そろっているか（12 + 10 + 3 + 5 = 30本、欠けがないか）

3が効く。ここが崩れたら対応表を間違えている。

## 段取り

1. `slime.js` と `tests/test-slime.js` を先に書く。判定が合っていることを確認する
2. `text.js` に本文を束ねる
3. `index.html` と `app.js`。**画像は今ある12枚のまま、全色で使い回す**
4. 動いてから、鉢の色替えで 5色 × 6景 = 30枚に増やす

30枚作ってから実装すると、直しが30枚に波及する。1色で動かしてから増やす。
